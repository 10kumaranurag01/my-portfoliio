# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm start                       # dev server on http://localhost:3000 (alias of `npm run dev`)
npm run build                   # tsc --noEmit, then production build to /dist
npm run preview                 # serve the built /dist
npm run typecheck               # tsc --noEmit on its own
npm run lint                    # eslint .
npm run format                  # prettier --write .
npm run format:check            # prettier --check . (CI-shaped, writes nothing)
```

Vite 7 + `@vitejs/plugin-react`, TypeScript in `strict` mode. `build` runs `tsc --noEmit` first; lint and format stay separate from it locally, and `.github/workflows/ci.yml` runs `lint`, `format:check` and `build` on every PR and on pushes to `main` (Node 24, `npm ci`). There is no test runner and no test files exist, so nothing runs tests in CI. Vercel builds independently of this workflow — a red CI run does not block a deploy.

ESLint 9 flat config in `eslint.config.js` (`js.configs.recommended` + `typescript-eslint` recommended + `react-hooks` + `react-refresh`, scoped to `src/**/*.{ts,tsx}`). `eslint-config-prettier` is extended **last**, so ESLint owns correctness and Prettier owns formatting with no overlapping rules — don't add `eslint-plugin-prettier`, formatting violations are not lint errors here. `typescript-eslint`'s type-checked configs are not enabled; the plain `recommended` set runs without a program, which keeps `npm run lint` fast.

Prettier runs on defaults (`.prettierrc` is `{}`), which already matched the codebase — double quotes, semicolons, 2-space, 80 columns. It does not reflow the contents of the multi-line Tailwind `className` strings, since those are string literals.

Deploys via Vercel (`.vercel` is gitignored). `vercel.json` pins `framework: vite` and `outputDirectory: dist`, because the Vercel project predates the migration and its dashboard settings still pointed at CRA's `build` directory — the deploy failed with `No Output Directory named "build" found`. `vercel.json` takes precedence over the dashboard, so the fix lives in the repo rather than in project settings. If someone later switches the dashboard preset to Vite, this file becomes redundant but stays harmless.

## Architecture

Single-page portfolio site. TypeScript + TSX, no router. `index.html` lives in the project root (Vite convention) and loads `/src/main.tsx`, which mounts `App`. `App` wraps a fixed list in `<CRTScreen>`: a skip link, `Header`, `Headerphone`, then `Home`, `Work`, `Capabilities` and `Contact` inside a `<main id="main">` landmark, then `Footer` and `Toaster`. The `<main>` carries `tabIndex={-1}` so the skip link moves focus and not merely the scroll position, and `scroll-mt-nav` so its landing clears the sticky header like every section. `App` also owns the `menuOpen` state: `Header` (the toggle) and `Headerphone` (the panel) are siblings that share no ref, so they coordinate through ids (`nav-menu-toggle`, `nav-menu`) and lifted state.

Navigation is anchor links (`#home`, `#work`, `#capabilities`, `#contact`) against `id`s on the section wrappers, so adding a "page" means adding a section component + an `id` + an entry in the `NAV_LINKS` array in `Header.tsx`. Each `NAV_LINKS` entry carries three fields, not one: `label` is the stylised terminal path shown to the visitor, `href` the target id, and `aria` a plain accessible name, because "~/" reads as "tilde slash" to a screen reader. The label and the id are allowed to differ: `~/stack` points at `#capabilities`, whose heading is `// 02 STACK`. `Headerphone` renders the mobile panel and owns everything an overlay owes the keyboard in one effect (focus in, Tab trapped, Escape out, body scroll locked, focus returned to the toggle on dismissal but not on navigation), which is what earns it `aria-modal`.

`index.html` is hand-maintained and sits outside the React tree, so it cannot import `src/data/resume.ts`. Anything mirrored from there has to be kept in sync by hand: the `<noscript>` fallback (name, email, LinkedIn, GitHub) and the absolute share URLs. The head carries `rel="canonical"`, Open Graph and Twitter card tags, all pinned to the live deployment domain `https://myportfolio.anuragsahu.site/`. The card is `twitter:card=summary`, not `summary_large_image`, because the only share asset is the square 512x512 icon and a large-image card centre-crops a square into a letterbox sliver. Note the deliberate, documented conflict: `resume.ts`'s `https` protocol entry and the resume source both still print a different host, and so does the built PDF; retiring that domain means three edits and a PDF rebuild.

`public/` is Vite's static-copy directory: files there are served from `/` verbatim (`/favicon.ico`, `/icon-192.jpg`, `/icon-512.jpg`, `/manifest.json`, `/robots.txt`). Anything imported from `src/assets` goes through the bundler and gets hashed instead, which is why the resume links pass an explicit `download={resumeFileName}` rather than a bare `download`. `manifest.json` is a real manifest now, not Create React App's sample: it names the site, the description that matches the `<meta>` tags, the two JPG icons and `#000402` for both `theme_color` and `background_color`. The old `logo192.png` / `logo512.png` are gone; the icons are `.jpg`, and the `type` fields say so.

**`src/componenets/` is misspelled on disk.** Every import depends on it. Don't rename it as a drive-by cleanup.

Two documents at the repo root are not this file. `PRODUCT.md` holds the strategic design context that `CLAUDE.md` deliberately does not: register, who the users are and what they are skimming for, the brand personality and the three words it locks, the anti-references, five design principles and the accessibility bar. It is the owner's stated intent, so read it before proposing anything that changes what the site is trying to do, and treat its "this voice is locked" clause as binding. `README.md` is the outward-facing summary (stack, commands, layout) and is no longer the CRA template.

### Styling — Tailwind, retro-CRT tokens enforced by override

All styling is Tailwind utilities in TSX. `src/styles/app.css` is the only stylesheet, imported once in `main.tsx`; it holds the `@tailwind` directives, the `--crt-*` custom properties, and a `@layer components` block with the CRT overlay layers. There are no SCSS files and no CSS modules.

Tailwind is wired through `postcss.config.js` (tailwindcss + autoprefixer), which Vite picks up automatically. If that file goes missing the build still succeeds but ships `@tailwind`/`@apply` unprocessed and every utility class dies — symptom is a ~3 kB `dist/assets/index-*.css` instead of tens of kB (currently ~17.79 kB). `package.json` is `"type": "module"`, so `postcss.config.js` and `tailwind.config.js` are both ESM (`export default`, not `module.exports`).

`tailwind.config.js` overrides (not extends) three scales, so the system is enforced rather than merely offered:

- **`spacing`** — 8px metric only: `1` = 8px, `2` = 16px, … plus a `0.5` = 4px half-step, a `nav` = 100px token for the sticky header's height (used as `scroll-mt-nav` on every section and in `min-h-[calc(100vh-theme(spacing.nav))]` on the hero, so the 100px lives in one place), and the page gutters (`page`, `page-md`, `page-base`, `page-sm`). Off-grid values must be written as arbitrary values (`p-[13px]`), which makes them visible in review. The first three gutters are `vmax`; `page-sm`, the narrowest-viewport one, is a fixed `16px` and must stay that way. `vmax` keys off viewport **height** in portrait, so `1vmax` resolved to 8.44px on a 390x844 phone: the gutter shrank as the screen narrowed, which is backwards.
- **`colors`** — project palette only, so a stray `bg-blue-500` generates no CSS instead of shipping an off-palette colour. The palette is the retro-CRT set: `void` (page base), `carbon` / `carbon-raised` / `carbon-sunk` (window chrome fills), `phosphor` / `phosphor-bright` / `phosphor-dim` (body text and headings), `cyan` / `cyan-dim` (links, focus ring, active state), `amber` (the single highlight tier, see below), `mute` (disabled text), `line` / `line-bright` / `line-strong` (1px borders), and `bar-red`/`bar-orange`/`bar-yellow`/`bar-green`/`bar-cyan`/`bar-blue` (the mandated 6-stripe rainbow, in that order). There is no `accent` token any more — the previous pink/orange accent system and its `canvas`/`slate`/`ink`/`teal`/`smoke`/`rule`/`dot` colours were removed wholesale in the retro-CRT overhaul (see "Removed" below), and there is no `black` or `white` either: the shared design law forbids pure black, so `void` is `#000402`, a near-black tinted toward the brand hue. The luminance shift off `#000000` is negligible, so no measured ratio depends on it, but nothing should reintroduce `#000` as a token.

  The three `line` values are not a light/medium/dark ramp, they are two different jobs, and collapsing them undoes the point. `line` (`#3a3a46`) and `line-bright` (`#4d4d5c`) are **decorative only**: dividers, table rules, card borders, the bezel hairline. `line-strong` (`#6b6b7d`) is for **interactive boundaries**: buttons, form inputs, the `<details>` disclosure control, anything a visitor clicks. It is the only one that clears WCAG 1.4.11's 3:1 bar for non-text UI components (4.03:1 on `void`, 3.77:1 on `carbon`). The pre-critique `line` was `#23232b` at 1.35:1, which is why buttons did not read as buttons. A control that draws its own boundary takes `line-strong`; a rule that only separates content takes `line`. Note that `line-bright`, `cyan-dim` and `carbon-raised` are currently unreferenced in `src/`: unlike the animations below, the palette keeps its scale intact rather than pruning to the exact set in use, so their presence is not evidence that anything reads them.

  `amber` is the site's one highlight tier and is reserved for a single action: the resume download. PRODUCT.md names "a recruiter reaching the resume download" as the success metric, so amber exists to make that the loudest thing on screen. Spending it anywhere else spends it everywhere.

- **`screens`** — the site's breakpoints are all max-width and named `mq-1367`, `mq-1100`, `mq-900`, `mq-786`, `mq-600`, `mq-425`, listed widest first so narrower queries win. There are no `sm:`/`md:`/`lg:` variants; `mq-900:gap-2` means "at 900px and below".

One family, monospace-only: JetBrains Mono (400/500/700), loaded via `<link>` in `index.html` (preconnect, then `rel="preload" as="style"`, then the stylesheet), not a CSS `@import`. The preload is deliberate: this is the only path to the only font family the site has, so it competes for priority with nothing, and shortening the CSS-then-woff2 chain keeps the first paint out of the generic monospace fallback, whose metrics differ enough to reflow visibly. `fontFamily.sans`/`display`/`mono` all alias the same stack so nothing falls back to a proportional face. Font sizes larger than Tailwind's defaults are `text-display`, `text-display-sm`, `text-display-xs`, plus a `text-2xs` for meta/label text. `.text-glow` / `.text-glow-cyan` (the phosphor/cyan text-shadow utilities used on headings) are hand-written `text-shadow` rules in `app.css` (around `:170-176`), not generated from a token. `boxShadow` is one entry, `glow-cyan`, and it is unrelated to those: it backs the `shadow-glow-cyan` box-_shadow_ utility used on the trigger buttons' hover state and the footer's channel icons. The old `boxShadow.glow` was removed once nothing referenced `shadow-glow`.

`tailwind.config.js`'s `keyframes`/`animation` define exactly two entries, and both are consumed: `scan` (scanline sweep, drives `.crt-sweep`) and `drift` (matrix grid, drives `.crt-grid`). `flicker` and `caret` were deleted with their last consumers, the same way `framer-motion` and `typewriter-effect` were dropped from `package.json`. Motion is pruned strictly: an animation whose consumer goes, goes, so there is no spare keyframe here to reach for and adding one means adding its consumer in the same change. The `@media (prefers-reduced-motion: reduce)` block in `app.css` sets `animation: none` on the two animated CRT layers and `scroll-behavior: auto` on `html` (anchor-nav scrolling is otherwise `smooth`); the mobile panel's slide handles this itself with `motion-reduce:transition-none`. Any new motion joins one of those two. `plugins: []`; there is no Tailwind plugin registered.

### CRT shell

The portfolio used to ship a light-themed `design`/`dev` dual-layout mode (toggle button, `<html data-ui="...">`, neon cursor, `design:`/`dev:` Tailwind variants) alongside the CRT rebuild so every intermediate commit kept compiling. That mechanic — `src/componenets/UITheme.tsx`, its `UIThemeProvider`/`useUITheme`/`LayoutToggle`/`Block` exports, the `--ui-*` custom properties, and the `design:`/`dev:` variant plugin — has been deleted; there is now exactly one visual theme.

`App.tsx` renders the skip link, the header pair, the `<main>` landmark and the footer directly, wrapped in `<CRTScreen>` (`src/componenets/crt/CRTScreen.tsx`). `CRTScreen` returns a fragment — it adds no wrapper element, so it creates no scroll or stacking container over the sticky header — and renders four fixed, `aria-hidden`, `pointer-events: none` overlay layers after its children: `.crt-grid` (drifting matrix grid, `z-index: -1`), `.crt-scanlines` (static fine lines plus an animated sweep bar, `z-index: 200`), `.crt-vignette` (edge darkening, `z-index: 201`), `.crt-bezel` (rounded inset frame, `z-index: 202`). All four are defined in `app.css`'s `@layer components` and tuned by the `--crt-*` custom properties declared on `:root`. Those z-indices are why the skip link is `focus:z-[300]`: anything lower puts it behind the scanlines and bezel.

**`--crt-vignette-strength` is a legibility budget, not a taste knob.** Read the long comment above `.crt-vignette` in `app.css` before touching it. The page base is already near-black, so the layer cannot darken the background: it only darkens the **foreground** sitting under it, and every point of strength is spent straight out of the contrast budget. The rule now carries a vertical mask (transparent at `y=0`, opaque from 140px down, symmetric at the bottom) and a much lower alpha than before. The mask attenuates the vertical axis only, so the horizontal edges are unmasked and the binding constraint is the **left/right gutter**, not the centre: at `page-sm` that puts text 16px from the edge, where composite alpha has to stay under 0.166 for `phosphor-dim`/`mute` at `text-2xs` (4.5:1) and under 0.144 for `line-strong` on `carbon` (1.4.11's 3:1). At strength `0.22` the measured total is ~0.135, so both clear with very little room. Raising the strength or the 120px blur radius spends that margin and breaks WCAG AA. Check the gutter, not the centre. The same reasoning is why `Footer`, `Contact`'s labels and `Header`'s nav links use `text-phosphor` rather than `-dim`: they all sit in the unmasked gutter, and `phosphor-dim` measures 2.23:1 under the header band.

Four more shared primitives live in `src/componenets/crt/` (all re-exported from `crt/index.ts`):

- `RainbowBar` — the 6 `bar-*` stripes, `flex`, each `flex-1`; `height` is `"thin"` (4px) or `"thick"` (8px).
- `Window` — the charcoal container used for every card/panel: `bg-carbon`, `border border-line` (decorative, it separates rather than invites a click), rounded, and a title strip holding a monospace `title` plus an optional `meta` label. There are no chrome dots: twelve instances meant 36 dots with no state behind them, which made them the page's highest-count decoration and the only non-systemic use of the `bar-*` rainbow, so the 1px border and the strip carry the chrome alone. The title is `text-sm text-phosphor-bright`, because on `Work` it holds the company name and an 11px dimmest tier made the marked-up heading the least visible string in its own card. `titleAs?: "h2" | "h3" | "p"` defaults to `"h3"`; pass `"p"` for a decorative panel. `Home`'s hero terminal does exactly that, because an unconditional `<h3>` there landed between the `h1` and the first section's `h2` and broke the outline (WCAG 1.3.1).
- `SectionShell` — the section wrapper: `<section id>`, `scroll-mt-nav` (so anchor-nav landings clear the sticky header) + a `// NN LABEL` heading (a space, not an em dash) + a `RainbowBar` divider + children. This replaces the old `Block`. The three sections are `// 01 SELECTED WORK`, `// 02 STACK` and `// 03 CONTACT`.
- `triggerClass` / `triggerClassSm` / `triggerClassPrimary` / `triggerClassSmPrimary` — plain string constants for the terminal-style `[ LABEL ]` trigger buttons and links, so the class strings don't get copy-pasted again; `Sm` is the smaller `px-2 py-0.5` padding. **Two tiers, and only two.** The secondary pair is outlined `border-line-strong` (not decorative `border-line`, per WCAG 1.4.11) with `text-phosphor` labels, and is imported by `App` (the skip link), `Home`, `Capabilities` (the `<details>` summary) and `Contact` (the submit button) plus `Header`'s nav-panel close button. The primary pair is the amber resume call to action, imported by `Header`, `Home` and `Footer`: filled `bg-amber` on `text-void` and `text-sm` rather than `text-2xs`, because outlined amber at 11px lost to the 14px nav links beside it on both size and contrast (phosphor 16.80:1, amber 13.65:1), leaving hue as the only priority signal, which is nothing under deuteranopia. Fill is the tier signal; hover inverts to the outline and 13.65:1 holds both ways, so neither state is the legible one.

Every mode-dependent CSS hook (`design:`/`dev:` variants, `--ui-*` properties, `.ui-block*`, `.neon-cursor*`, `.tok-*`) is gone along with the components that used it — styling is one static Tailwind config now, no data-attribute branching.

### Firebase

`src/firebase.ts` initializes the app and exports `db` (Firestore only — no Auth, no Storage). The config is hardcoded, not env-driven. The only write path is `Contact.tsx`, which `addDoc`s `{name, email, message}` into the `contacts` collection and reports via `react-hot-toast`. Anyone can post to that collection; **access control lives in Firestore security rules on the Firebase console, not in this repo.** That is unchanged by the form's hardening, which is a spam floor and nothing more: the three fields now have visible `<label htmlFor>` labels, `name` and `autoComplete` attributes (`name`, `email`), and there is a fourth `display: none` honeypot input named `tx-nonce` whose contents cause the submit to drop silently, with a `console.warn` as the only trace so a bot learns nothing. The honeypot is deliberately not called `company`: that is the exact heuristic Chrome's `organization` autofill and password managers match on (`autocomplete="off"` is widely ignored there), and a real visitor whose manager filled it got a `[ TRANSMIT ]` button that silently did nothing forever. The failure toast hands back the `mailto` address from `resume.ts` rather than just saying "Error", because the write fails for ordinary reasons: offline, corporate proxy, security rules.

### Content locations

`src/data/resume.ts` is the single source of resume content — every name, title, date, company, bullet, skill and contact address rendered anywhere on the site is exported from here, traced back to the resume in `docs/superpowers/plans/resume-source.tex`. No component hardcodes resume strings; the mandated verbatim UI copy (the hero `h1`, and the `[ LABEL ]` strings on the triggers) is UI copy, not resume data, and stays in its component. What it exports and who reads it:

- `profile` — name, title, location. Read by `Header`, `Home`, `Footer`.
- `summary` — the one-paragraph bio. Read by `Home`. It is a trim of the resume paragraph, not a rewrite: the 25-technology comma chain came out because `skillGroups` already holds every keyword in it, and the opening role label came out because the hero prints `profile.title` directly above it.
- `protocols` — contact addresses (`mailto`, `tel`, `geo`, `linkedin`, `github`, `https`), each `{protocol, label, value, href}` with `href: null` for `geo`. `protocol` is the machine key (React keys, the `Footer` lookup, `isExternalProtocol`); `label` is what a non-engineer reads in the table's first column, because a recruiter should not have to know that "geo" means an address and "https" a website. Read by `Header` (the email link), `Contact` (the protocol table), `Footer` (the channel icons).
- `isExternalProtocol` — the shared predicate for whether a protocol gets `target="_blank"` + `rel="noreferrer"`. `mailto:` and `tel:` hand off to a local app, so a new tab is meaningless there and wrong for `tel:`. Lives here so `Contact`'s table and `Footer`'s icons cannot disagree again.
- `skillGroups` — the capability lists (`{id, label, items}`). Read by `Capabilities` only.
- `experience` — the work history, as `{id, company, role, period, cluster, bullets, stack}`. One entry per resume subhead, so the current job is four entries sharing a company, role and period. Read by `Work`, which groups them (see below) rather than rendering one card each, and by `Home`, which picks the current role by the `"Present"` marker in `period` and lists that company's `cluster` strings.
- `credentials` — education/certifications. Read by `Footer`.
- `resumeFile` / `resumeFileName` — the re-exported module import of `src/assets/Kumar_Anurag.pdf`, plus its plain filename. Read by `Header`, `Home` and `Footer`. All three links carry the same three attributes: `download={resumeFileName}` (a bare `download` would save the content-hashed name Vite emits), plus `target="_blank"` and `rel="noreferrer"` as the fallback for browsers that ignore `download` on a PDF. Replacing the PDF is enough; all three links follow.

Two sections derive rather than mirror, and both derive from the data's own shape so nothing is hand-tuned to today's counts. `Work` renders **one card per employment tenure, not per resume subhead**: it reduces `experience` into tenures keyed on company + role + period, and prints the shared clusters as `h4` subheads inside one card, which is what they are in the resume. One card per entry printed the same three lines four times and made a fifteen-second skim read five employers where there are two. There is no carousel: no slide state, no swipe, no prev/next triggers, no dot navigation. `Capabilities` weights its disclosure by group size against the mean of `items.length`, so groups above the mean take the full row in two columns and the lighter ones print in full; only the long tails go behind a native `<details>`, which keeps every term in the DOM for in-page search and scrapers and needs no JS.

Local images are ES-module imports from `src/assets`; the `src/componenets/crt/` primitives and section components otherwise use only Tailwind utilities and `react-icons`, no other image assets.

### Removed in the Vite/TypeScript migration

`Timeline.jsx`, `Testimonial.jsx` and `src/assets/data.json` were unrendered dead code carrying class names from the deleted SCSS; they were dropped rather than converted. `react-scripts`, `sass`, `web-vitals` and the `@testing-library/*` packages went with them (nothing imported them, and there was no `reportWebVitals` call or test file). Recover any of it from the history if it turns out to be wanted.

The retro-CRT overhaul that followed removed the rest of the pre-existing system: `Services.tsx` was renamed to `Capabilities.tsx` (the component itself was already rewritten); `src/componenets/UITheme.tsx` and the whole `design`/`dev` dual-layout mode were deleted (see "CRT shell" above); the superseded `tailwind.config.js` palette entries (`accent`, `canvas`, `slate`, `ink`, `teal`, `smoke`, `rule`, `dot`), `boxShadow` entries (`window`, `neon`) and keyframes/animations (`animateSvg`/`chevron`, `upanddown`/`float`, `upupdowndown`/`float-lg`) were removed once nothing in `src/` referenced them; and the `framer-motion` dependency was dropped from `package.json` once its last import was replaced. `src/assets` still holds several dozen now-unimported PNGs, a stray JPG and `Deedy_CV.pdf` from before the rewrite — unimported files aren't bundled, so they were left on disk rather than cleaned up.

### Removed applying the design critique

The critique pass cut features, not just tokens, so a doc or a plan referring to any of the following is out of date. `Work`'s carousel is gone whole: slide state, swipe handling, prev/next triggers and dot navigation, replaced by the stacked one-card-per-tenure list. `Home`'s boot telemetry went with it. That was a typewriter animation of invented strings ("booting kandyr agent runtime...", "status: ok"): PRODUCT.md names fake typing animations as an anti-reference by name, and it was the largest above-the-fold element after the `h1` while carrying no role-fit information. The same terminal frame now prints the current role's workstreams out of `resume.ts`, and `typewriter-effect` was dropped from `package.json`. `Window`'s traffic-light dot triad is gone. Tokens went the same way as their consumers: `keyframes`/`animation` `flicker` and `caret`, `boxShadow.glow`, and `colors.black` / `colors.white`. In `public/`, Create React App's sample `manifest.json` and its `logo192.png` / `logo512.png` were replaced by a real manifest and `icon-192.jpg` / `icon-512.jpg`, and `README.md` stopped being the CRA template. Nothing here was kept "in case"; the rule is that a token or a dependency leaves with its last consumer.
